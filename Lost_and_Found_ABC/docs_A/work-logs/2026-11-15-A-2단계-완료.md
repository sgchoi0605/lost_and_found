## 수정 범위

`features/account/`, `shared/`, 루트 설정과 문서를 수정했습니다. **features/reports, features/discovery, features/operations는 변경하지 않았습니다.** 기존 C 메인에 있던 A의 로그인·알림 컨트롤은 공통 layout.js에서 연결했습니다. 메인 알림 서랍의 예시 내용은 런타임에 비워 실제 알림 페이지로 이동시킵니다.

신규 주요 파일: account.validation.js, admin.cli.js, frontend/js/account-ui.js, shared/backend/request.middleware.js, 본 가이드·작업 기록·검증 이미지. 기존 파일에 있던 빈 서비스·저장소·화면을 실제 구현으로 교체했습니다.

## 검증 결과

환경: Windows / Node.js 24.15.0 / pnpm 10.34.9.

| 검증 | 결과 |
|---|---|
| `corepack pnpm test` | 22개 통과, 실패 0 (계정 9 + DB 8 + 서버 5) |
| `corepack pnpm build` | 20개 HTML 화면 빌드 통과 |
| `corepack pnpm db:init` | 로컬 DB 버전 2 적용, 9개 테이블 확인. 테스트 계정 삽입 없음 |
| Chrome 실제 폼 가입·로그인·로그아웃 | 통과 |
| 메인 로그인 사용자 표시·알림 버튼 연결 | 통과 |
| 알림 없음·생성 후 조회·개별 읽음·모두 읽음 | 통과 |
| 일반 회원의 관리자 화면 접근 | 거부 확인 |
| 관리자 사용자 제한·해제 | UI 및 DB 변경 확인 |
| 모바일 375×812 | 가입·알림·사용자 관리 가로 넘침 없음 |
| Vite 실제 개발 프록시 | 로그인 쿠키 유지·메인 이동·알림 조회 통과 |
| 브라우저 JavaScript pageerror | 0건 |

자동 테스트는 입력 오류·중복 가입·역할 주입 방지·비밀번호 해싱·세션 회전/만료/폐기/DB 재연결·알림 소유권·읽음 멱등성·권한·신고 제한 만료·감사 이력·출처/JSON 검사·시도 제한·DB 업그레이드를 확인합니다. 정적 경로·모듈·비공개 파일 보호도 검사합니다.

브라우저 확인은 임시 메모리 DB와 `example.invalid` 테스트 계정으로 실행했습니다. 실제 사용자 DB에 테스트 계정·알림을 넣지 않았습니다. 테스트용 브라우저 도구는 임시 폴더에 설치했으며 프로젝트 의존성에는 추가하지 않았습니다. 기존 gstack browse 설치는 server.ts/playwright가 빠져 실행되지 않아, 임시 Playwright와 설치된 Chrome으로 동일 흐름을 확인했습니다.

초기 node_modules의 링크가 불완전하여 Express 하위 모듈과 Vite 모듈이 누락됐습니다. `corepack pnpm install --frozen-lockfile --force`로 동일 잠금 파일의 설치를 복구한 뒤 검증했습니다. 의존성 버전과 pnpm-lock.yaml은 변경하지 않았습니다.

## 팀원들이 이어서 할 일

**B:** 신고 등록에 requireAuth/requireCanReport 적용, 수정·삭제 소유권 검사, 사진 업로드 정책 조율.

**C:** 실제 검색·매칭·통계 구현, 매칭 처리 트랜잭션에서 createNotification 호출.

**D:** 인계·보관·폐기 구현, 상태 변경/기한 사건에 createNotification 호출, 반복 생성 방지.

**전원:** 3단계 전체 업무 통합 테스트. 현재 A의 자동 검증 통과가 미구현 B/C/D의 통합 완료를 의미하지는 않습니다.

아이디 찾기·비밀번호 재설정·메일/푸시 발송은 이번 필수 범위 밖이며 미구현입니다. 기본 관리자 계정은 생성하지 않았으므로 각자 가입 후 로컬 admin:promote 명령을 사용하세요.

전체 예제와 실행 방법은 [A 완료·연동 가이드](../A_구현완료_연동가이드.md), 요청·응답은 [API 계약](../../shared/contracts/api-contract.md)을 확인하세요.
