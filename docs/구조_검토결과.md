# 역할분담 설계안 대조 결과

> 후속 변경 (2026-11-12): 아래 내용은 11월 11일 당시의 검토 기록입니다. 이후 Express 서버, 짧은 URL, 기능별 연결 확인 Router와 프론트엔드 정적 공개 범위를 구현했습니다. 현재 실행 방법은 README를 참고하세요. DB·인증·업무 API는 여전히 미구현이며 전체 DB 설계 담당은 A로 합의했습니다.

검토일: 2026-11-11. 기준: 프로젝트 상위 폴더의 `Lost_and_Found_역할분담.md`.
검토 범위는 폴더·파일·담당 경계·협업 안내입니다. 백엔드 구현이나 과제 기능 완료 검증은 아닙니다.

## 일치하는 부분

- A/B/C/D 기능 폴더 및 공통 shared 구조가 있습니다.
- A 4개, B 5개, C 6개, D 5개로 HTML 20개와 각각의 JS, 기능별 CSS 파일이 있습니다.
- 명시된 백엔드·SQL·테스트 파일은 빈 골격으로 존재합니다.
- 기존 메인·로그인·신고 화면 및 이미지의 새 위치가 존재합니다.
- 실제 DB, 환경 비밀값, 의존성 폴더, 빌드 출력은 Git 제외 대상입니다.

## 의도적으로 다음 단계로 미룬 부분

| 항목 | 현재 상태 / 판단 |
|---|---|
| Express·SQLite | 사용자 요청에 따라 미구현. server.js를 실행해도 서비스가 시작되지 않음 |
| DB 파일 | database/.gitkeep만 존재. lostfound.db를 미리 생성하지 않는 것이 맞음 |
| API·DB·상태값 계약 | 제목과 작성 예정 안내만 있음. 확정 스키마로 사용하면 안 됨 |
| 공통 api/layout/auth-guard | 빈 골격. 실제 공통 헤더·인증 가드로 사용할 수 없음 |
| 신규 17개 화면 | 구현 예정 화면. CSS·JS도 대부분 빈 파일이며 과제의 기능 구현 조건 충족 전 |
| 짧은 URL·API URL | 미구현. 현재 /features/기능/frontend/화면.html 사용 |
| 정적 공개 범위 | 현재 Vite는 개발 용도. 운영 서버에서 frontend만 공개하는 설계는 다음 단계에 구현 |
| package-lock.json | pnpm 유지이므로 없음. 설계안에서 허용한 선택이며 pnpm-lock.yaml 사용 |
| 브랜치 이름 | 예시 feature/account 대신 사용자 요청대로 A/B/C/D 사용 |

## 아직 정리되지 않은 부분

1. **CSS 분리가 완료되지 않았습니다.** base.css로 기본 규칙만 나눴고 기능별 규칙은 components.css에 남아 있습니다. 역할분담 5절의 기능별 CSS 이관은 미충족입니다. A 총괄로 각 기능 담당자와 규칙·미디어 쿼리를 함께 옮겨야 합니다. 현재 각 기능 CSS는 빈 시작점입니다.
2. **알림 이벤트가 C의 메인 JS에 남아 있습니다.** 알림 책임은 A이므로 A/C 협의 후 account 또는 A가 관리하는 공통 모듈로 옮겨야 합니다. 현재 notifications.js는 비어 있습니다.
3. **고정 예시 데이터가 UI에서 충분히 명시되지 않았습니다.** README와 버튼 안내에는 데모 표시가 있지만 메인의 매칭·알림 콘텐츠에도 예시임을 직접 표시하는 작업이 남아 있습니다.
4. 루트 assets에는 이전 이미지 복사본이 남아 있습니다. 실제 메인은 features/discovery/frontend/assets를 참조하므로 C는 새 경로를 수정해야 합니다.
5. .figma 및 일부 원본 도구 설정은 보존되어 있으나 일반 로컬 실행은 package.json과 vite.config.ts를 기준으로 합니다. Figma 배포 스크립트는 이번 개편 후 검증하지 않았습니다.
6. docs/sequenceDiagram.drawio는 기존 sequence_diagram_원본.drawio의 복사본입니다. 개선본이라고 간주하면 안 됩니다. meeting-notes는 자리만 확보되어 있습니다.

따라서 **파일 골격은 준비됐지만 설계안 전체를 구현·이관 완료한 상태는 아닙니다.** 앞선 준비 단계의 완료 표현과 기능 완료를 구분해야 합니다.

## 팀원 혼동을 줄이기 위한 보완

- 루트 팀원_작업가이드.md에 역할별 20개 화면과 CSS/JS 위치를 명시했습니다.
- Git LFS, pnpm 미설치 시 실행 방법, PowerShell 실행 정책 오류 대응을 설명했습니다.
- clone·브랜치 전환·최신 main 반영·경로별 add·commit·push·PR·충돌 대응을 안내했습니다.
- 폴더 소유권은 협업 규칙이며 브랜치의 접근 제한 기능이 아님을 명시했습니다.
- 초대·리뷰·브랜치 보호는 실제 GitHub 설정과 별개임을 구분했습니다.

이 검토에서는 기존 기능 코드를 추가 구현하지 않고 미완료 사항을 기록했습니다. 실제 서비스 전에는 권한 검사와 API 연동을 별도로 검증해야 합니다.
