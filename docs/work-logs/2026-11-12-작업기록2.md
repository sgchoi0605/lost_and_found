## 기준 문서와 적용 방향

사용자 지시에 따라 `Lost_and_Found_역할분담.md`를 우선 기준으로 삼았다.
`최성규/diagram`의 ERD·시퀀스·유스케이스·아키텍처를 확인하고, 역할분담 문서와 맞는 컬럼과 관계를 참고했다.
이전에 합의한 대로 전체 기능의 DB 스키마 설계는 A가 작성했다.

역할분담 문서와 다른 다이어그램 부분은 다음처럼 처리했다.

| 다이어그램 | 이번 구현 |
|---|---|
| Supabase + PostgreSQL | 기존 합의와 역할분담 문서대로 Express + SQLite 유지 |
| 간소화된 6개 테이블 | 역할분담 문서의 8개 테이블 유지 |
| ACTIVITY_LOGS | audit_logs로 이름 대응 |
| REPORTS.photo_urls | report_photos 테이블로 분리 |
| REPORTS의 보관·폐기 필드 | storage_records 테이블로 분리 |

## 완료한 코드

### 1. 공통 DB 연결

`shared/backend/database.js`에 Node 내장 `node:sqlite` 연결 함수를 구현했다.

- `openDatabase()`로 연결하고 사용한 쪽에서 `close()`한다.
- 기본 DB 파일은 `database/lostfound.db`다.
- `.env`의 `DATABASE_PATH`로 변경할 수 있고 상대 경로는 프로젝트 루트 기준이다.
- DB 파일의 부모 폴더가 없으면 만든다.
- 모든 연결에 외래 키 검사를 활성화하고 잠금 대기 시간을 5초로 설정한다.
- import나 웹 서버 시작만으로 DB를 만들거나 초기화하지 않는다.

### 2. 초기화 명령

`shared/backend/init-db.js`와 `pnpm db:init` 명령을 구현했다.

- account → reports → discovery → operations 순서로 스키마를 적용한다.
- 전체를 트랜잭션으로 묶어 중간 오류가 생기면 롤백한다.
- 반복 실행해도 기존 데이터를 지우지 않는다.
- 외래 키 위반을 점검하고 `PRAGMA user_version=1`로 버전을 기록한다.
- 현재보다 높은 DB 버전이면 작업을 거부한다.
- 성공·실패에 관계없이 CLI의 DB 연결을 닫는다.
- 기존 컬럼 변경을 자동 처리하는 마이그레이션 기능은 아니다.

### 3. 기능별 스키마

| SQL 파일 | 생성 테이블 |
|---|---|
| features/account/account.schema.sql | users, notifications, audit_logs |
| features/reports/reports.schema.sql | reports, report_photos |
| features/discovery/matching.schema.sql | matches |
| features/operations/operations.schema.sql | handover_requests, storage_records |

외래 키, 필수값, 중복 제약, 상태 코드 CHECK, 조회용 인덱스를 추가했다.
트리거로 매칭·인계·보관 관계의 LOST/FOUND 방향을 검증하고, 등록한 신고의 유형 변경을 막는다.
인계 승인(APPROVED)과 실제 완료(COMPLETED)를 구분하며 완료 시 수령인과 완료 일시가 필요하다.
이력의 상세 JSON은 유효한 JSON인지 검사한다.

연결·초기화·각 테이블·트리거·테스트에는 역할을 설명하는 한글 주석을 코드 묶음별로 작성했다.

### 4. 실행 안내와 상태 기록

- package.json: `db:init`, `test:db` 명령, Node 최소 버전 22.13 추가
- .env.example: DATABASE_PATH 예시 추가
- shared/contracts/database-schema.md: 현재 컬럼·관계·제약·ERD 차이 기록
- README, 팀원 가이드, 결정 기록, 구조 검토 기록, AGENTS.md: 현재 구현 상태 반영

Node 24.14에서 검증했다. 이 버전의 내장 SQLite는 ExperimentalWarning이 표시되지만 테스트와 초기화는 정상 완료됐다.
추가 네이티브 DB 패키지는 설치하지 않았다.

## 검증 결과

- DB 테스트 8개 통과: 8개 테이블 생성, 파일 저장·재연결·재초기화 보존, 외래 키·중복·값 제약, 매칭 유형·점수, 인계·보관 유형, 승인/완료 구분, 오류 시 롤백, 버전 검사
- 기존 Express 서버 테스트 5개 통과
- `pnpm build` 성공
- `pnpm db:init`을 실제 프로젝트에서 두 번 실행해 8개 테이블 생성과 재실행 성공 확인
- `database/lostfound.db`가 Git 제외 대상임을 확인

실제 로컬 DB에는 사용자·신고 등 샘플 데이터를 넣지 않았다. 테스트 데이터는 메모리 또는 임시 DB에만 넣고 종료 후 정리한다.

## 실행 방법

```powershell
corepack pnpm db:init
corepack pnpm test:db
corepack pnpm start
```

pnpm이 설치되어 있으면 앞의 corepack은 생략할 수 있다.
GitHub에는 코드·SQL·문서·테스트를 반영하고 실제 DB 파일은 올리지 않는다.
